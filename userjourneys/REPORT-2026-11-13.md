# User journey report — MLAICC Manager, branch `claude/user-journeys`

Run on 2026-11-13 against the jar built from the checked-out branch (`mvn -q -DskipTests package`, build time 2026-11-13T19:55:52Z), started in a scratch directory with only `static/`, `default-disciplines.json` and `default-rankings.json` copied in. Ports 5000/5001 were free before and are free again; the server is stopped. Nothing in the repo was modified (git status unchanged, root `data.json`/`relays.json`/`competition.json`/`disciplines.json` untouched).

All 13 journeys with all variations were played through the REST API (the calls the frontend makes). After every step a state check ran: every result has a start, one result per start, a result's competitor/discipline agree with its start, every lane and team member points at an existing start, one lane per start, one lane per competitor and relay, one start per lane, `/api/rmgmt/overview` without `issues`/`data_issues`, `/api/rankings/results` lists only existing starts, API counts agree with `data.json`, `relays.json`, `teams.json`. Three things were also checked in the real pages with the built-in browser (Todos page, barcode search on port 5001, bulk add); they are marked "browser".

Test fixture: 7 invented competitors (Alpha One..Four of "SV Alpha", Beta One..Three of "SG Beta"), 38 starts in Miquelet O/R, Vetterli O/R, Colt, Donald Malson O, Whitworth O/R, default rankings plus a hand-made "4_Whitworth O/R" (two entries), 2 meet days with 5 + 4 relays, automatic lanes, 9 results, 3 teams.

**Result: no journey left the system in an invalid state by the checks above. 1 journey is only possible in a roundabout way, 5 variations deviate from the journey text, and 3 real defects were found (one of them lets invalid results into the rankings).**

## 2. Deviations (alerts), most severe first

### (a) Application defects / invalid data

**A1 — The result API does not check the shots (enter_results V3). Severity: high.**
- Calls (all on port 5001, the result station's port):
  - `POST /api/results {"start_id":"3-1-1","value":81,"entries":[9,9,9,9,9,9,9,9,9]}` (9 shots) → **200**, stored as result 5.
  - `POST /api/results {"start_id":"4-1-1","value":110,"entries":[10 × 11]}` (11 shots) → **200**; `GET /api/rankings/results` then ranks Alpha Four first in 1_Miquelet_O with **score 110**, `freq_counts {"10": 11}`.
  - `POST /api/results {"start_id":"6-1-1","value":999,"entries":[15,12.5,-3],"override_value":-5}` → **200**, ranked with score 24.5.
  - `POST /api/results {"start_id":"7-1-1","value":5,"entries":null}` → **200**, ranked with score 5.
  - On port 5000: `PUT /api/results/1 {"value":500,"entries":[50 × 20],"version":1}` → **200**; ranking score **1000**, team 9_Gustav Adolph total **1179**.
- Expected (journey): "the shots do not add up to 10 … refused, nothing stored".
- What happens: only the page checks (`static/js/modules/results.js:441-449`, read in code, not clicked through). The server stores whatever arrives; `value` is ignored and the score is the sum of `entries`.
- State afterwards: referentially valid, but results that cannot exist (more than 100 points) are in the individual and team rankings.
- Source: `src/main/java/com/competition/service/ResultService.java:79` (`createResult`, checks only `start_id`) and `:132-142` (`updateResult`, copies `value`/`entries` unchecked).
- The second half of V3 works: `start_id` "99-1-1" → 400 `Start 99-1-1 does not exist`; empty or missing `start_id` → 400.

**A2 — The Todos page lists teams that have no result at all (tie_break main). Severity: medium.**
- Verified in the browser on `http://localhost:5000/todos/` with the fixture's two Gustav Adolph teams and no Miquelet results: both teams appear with sum 0, "unvollständig", tie-break "fehlt".
- Expected: "the Todos page is empty" once the individual tie is settled. Before the first Miquelet result is in (or whenever two teams have equal, incomplete sums) it never is.
- Source: `static/todos/todos.js:47` — `if (!isTeam(data) && !hasResult(row)) continue;` skips individuals without a result but no teams; `complete: false` is not considered.
- No data is wrong; the page only reads `GET /api/rankings/results`.

**A3 — A truncated zip answers 500 instead of 400 (backup_restore V1). Severity: low.**
- `POST /api/backup/restore` with the first half of a valid backup zip → **500** `{"error":"Failed to restore backup"}`. Files unchanged, no safety copy written, so "refused, nothing changes" holds; only the status and message are wrong.
- All other invalid uploads answer 400 with the reason: not a zip, empty body, zip without `data.json`, `data.json` not JSON / not an object, `teams.json` an array, `catalog.json` not a catalog.
- Source: `src/main/java/com/competition/service/BackupService.java:236` catches only `ZipException`; the `EOFException` of a cut-off zip falls through to the generic handler in `resource/BackupResource.java:69`.

**Observations (no invalid state, but worth knowing)**
- A4 — `POST /api/competitors {"name":"","club":"SC Gamma"}` → 200, a competitor without a name; `year_of_birth: "1800"` and `country: "Atlantis"` are stored too. Only the pages validate these.
- A5 — A deleted ranking stays in a day's `ranking_ids` in `relays.json`: `PUT /api/rmgmt/days/day2/rankings {"ranking_ids":[2,26,28,17]}` → 200, `DELETE /api/rankings/17?version=0` → 204, `GET /api/rmgmt` still returns `[2,26,28,17]`; sending that same list back → 400 `17 is not an individual ranking of this meet`. The same after Danger Zone "Rankings" (all ids dangle, both days silently become "rest" days) and after a rankings import that renumbers a ranking. Tolerated on purpose (`RelayService.java:360-363`: "or only rankings that no longer exist"); the overview reports nothing. "Load Defaults" brings ids 1–67 back, so the days reconnect; a ranking created by hand continues at `next_id` (69).
- A6 — `POST /api/backup/restore` with a zip whose `data.json` is `{"hello":"world"}` → 200: every other file is removed and the app is empty. README only promises "a JSON object", so this is as documented; the safety copy brought everything back (verified).
- A7 — After a restore the id counters are the backup's: competitor id 8, handed out between backup and restore, was handed out again afterwards. Follows from "exactly in the state of the backup", but it is the one case where an id is reused.
- A8 — Putting a start by hand on a day whose rankings do not cover its discipline is accepted and not reported: `POST /api/rmgmt/assignments {"relay_id":"r9","range_id":"m50","lane_no":11,"start_id":"8-7-1","expected_assignment_id":null}` (Vetterli O on the Colt/Malson day) → 200, overview `issues: []`. README says manual assignment is not restricted, so plan_lanes' "every start is on a day whose rankings cover its discipline" only holds for the automatic assignment.
- A9 — A locked day answers 400, not 409 (`Cannot change lanes: 2027-06-25 is locked…`), and so does a deleted start at the result station. The journeys only say "refused", so this is not a deviation.

### (b) Only possible in a roundabout way

**B1 — change_discipline (main and V1): there is no call or button to change a start's discipline.**
- Tried: `PUT /api/competitors/5` with the start moved under discipline 17 → 200, but the starts are unchanged (README: "starts are not changed here"). No other endpoint exists (`StartResource` has only POST and DELETE; `static/js/modules/starts.js` only add and delete).
- What the organiser has to do (played through with Beta One, Vetterli O result 92, tie-break 15, lane r3/50m/5 on a locked day, team "SG Beta" of 24_Pforzheim):
  1. `DELETE /api/competitors/5/starts/5-7-1` → 204. This also deletes result 10, lane a12 (although the day is locked) and the membership in team 4, without a version check or a 409.
  2. `POST /api/competitors/5/starts {"discipline_id":17}` → 200 `5-17-1`.
  3. `POST /api/results {"start_id":"5-17-1","value":92,"entries":[…],"override_value":15}` → 200, new result id 12 (was 10).
  4. `POST /api/rmgmt/assignments {"relay_id":"r3","range_id":"m50","lane_no":5,"start_id":"5-17-1","expected_assignment_id":null}` → 400 while the day is locked; `PUT /api/rmgmt/days/day1/lock {"locked":false}`, assign → 200 (lane a39), lock again.
  5. `PUT /api/teams/4 {"name":"SG Beta","members":["6-7-1","7-7-1","5-17-1"],"tie_break":3.5,"notes":"n","version":1}` → 200 (Pforzheim counts Vetterli O and R).
- Afterwards the state is valid and the rankings are right (Vetterli O without the starter, Vetterli R rank 1 with 92, Pforzheim total unchanged at 180). Lost or changed on the way: the start id (labels and start cards already printed carry `5-7-1`), the result id, the lane id, and the result/tie-break/team must be typed again by hand.
- V1, harder case: if the team discipline does not count the new discipline, the membership cannot be restored. Beta Two moved from Miquelet O to Miquelet R: `PUT /api/teams/2` with `6-11-1` → 400 `Start 6-11-1 is not a start of 1_Miquelet_O (original) and cannot count for 9_Gustav Adolph`; the team stays with two members, `complete: false`, total 94.

**B2 — register_club V1: a second start in the same discipline cannot be entered in bulk add.**
- Browser: a row with rankings `VETO VETO XYZ REMO` counts 3 starts (Vetterli O once, Colt, Donald Malson O). `static/js/modules/bulkAdd.js:128` collects a row's disciplines in a `Set`.
- Roundabout: after "Add all", add the second start in the Starts section: `POST /api/competitors/8/starts {"discipline_id":7}` → 200 `8-7-2` (a third → `8-7-3`). That part of the variation ("gets the next start number") is correct.

### (c) The journey text is wrong about how the app works

**C1 — tie_break V1: "it wins the tie, nothing is left to do".**
- `POST /api/results {"id":1,…,"override_value":null}` for one of the two, the other keeps 11.0: `GET /api/rankings/results` ranks them 2 and 3 (the one with the value first), but the Todos logic still lists both.
- README: "lists the ranking entries still needing a tie-break value: same result and same number of 10s, 9s, … 1s as another entry of the ranking, with the tie-break **missing** or the same". Source: `static/todos/todos.js:40`.
- Corrected wording: "only one of the two gets a tie-break value: it is ranked first, both stay on the Todos page until the other one has a value too". The same holds for teams (V3: with only team B's tie-break set, B is rank 1, A rank 2, both still on Todos).

**C2 — build_team V3: "(e.g. Gustav Adolph and Halikko)".**
- `POST /api/teams {"discipline_id":39,"members":["1-1-1","2-1-1","3-1-1"]}` → 400 `Start 1-1-1 is not a start of 1_Miquelet_R (reproduction) and cannot count for 31_Halikko`. In the shipped catalog Gustav Adolph counts Miquelet O (`team_of: [1]`), Halikko Miquelet R (`[11]`).
- The rule itself works: the same three starts in 9_Gustav Adolph and in 11_GP of Versailles (`team_of: [1, 3]`) → 200.
- Corrected wording: "(e.g. Gustav Adolph and GP of Versailles, or Nobunaga and Nagashino)". README line 234 has the same wrong example.

**C3 — register_club V3: "that start is refused, the others are saved".**
- Browser: a short name that is not one of the meet's rankings (`XYZ`) marks the row red and disables "Alle hinzufügen" for the whole table ("1 Zeile mit Fehlern – Rote Zeilen korrigieren, um sie hinzuzufügen"); nothing is sent. Source: `bulkAdd.js:146-147` and `:370-371`.
- The text describes what happens only if a ranking disappears between opening the panel and saving: `POST /api/competitors/16/starts {"discipline_id":9}` → 400 `36_Pennsylvania_O is in none of this meet's rankings`, the competitor and the starts in disciplines 7 and 52 are saved.
- Corrected wording: "one entry names a ranking the meet does not have: the row is marked and nothing is added until it is corrected".

**C4 — enter_results V3: "refused" is true for the page only** (see A1). Either the server gets the check or the text should say "the page refuses to save".

**C5 — combined_ranking, starting situation.** The shipped default rankings contain the sums (Remington, Schulhof) but no ranking that ranks disciplines together; "Whitworth O/R" has to be created (`POST /api/rankings {"name":"4_Whitworth O/R","level":"individual","entries":[{"discipline_ids":[4]},{"discipline_ids":[14]}]}`). "The other listed below" is the row's `components` entry with `"further": true`.

**C6 — plan_lanes main, missing steps.** "sets the ranges, relay duration and break" needs `PUT /api/rmgmt/config/lock {"locked":false}` first (locked by default: `PUT /api/rmgmt/config` → 400 `Relay configuration is locked`), and the automatic assignment needs `PUT /api/rmgmt/config/auto-assign {"enabled":true}` (otherwise 400 `Auto assignment is switched off`). `PUT /api/rmgmt/ranges/{id}` needs `name` as well as `lane_count`.

**C7 — concurrent_edit V2: "the result is refused"** — with 400 `Start 4-7-1 does not exist`, not 409/404. In 30 simultaneous delete/enter rounds the result was refused 25 times and accepted-then-deleted with its start 5 times; no result without a start was ever left.

**Documentation, not journey:** port 5001 also serves `/i18n/*` and `/img/*` (`ResultsPortFilter.java`), which the README's list omits; the page needs them.

## 4. Not checked, and why

- **Browser-only output**: printing, Word/Excel export, start cards, race bibs, target labels with QR code, lane CSV. Only the API data they are built from was checked.
- **A physical barcode scanner**: the code was typed into the field (browser), which is what a keyboard-wedge scanner does.
- **Page-side validation and conflict handling**: the result page's "10 shots" check, the 409 reload behaviour and the Danger Zone switches were read in code, not clicked through. Clicked through: Todos page, start search on port 5001, bulk add with an unknown short name.
- **"Only reaches port 5001"** was tested as "only uses port 5001"; the firewall separation is outside the app.
- **External backup / backup receiver** (`--backup-server`): no journey covers it.
- **`tools/testfeeder`** was not used; the hand-made fixture was enough.
- **German API messages** (`lang` cookie): all calls ran with the English default.
- **Replacing a lane without `expected_assignment_id`**: per `RelayService.java:626-690` the lane's start is replaced; both attempts ran into another rule first, so this is read from code only.

The scripts were kept in a local scratch directory and are not part of the repository (`j_setup.py`, `j_register.py`, `j_lanes.py`, `j_late.py`, `j_results.py`, `j_tie.py`, `j_combined.py`, `j_team.py`, `j_change.py`, `j_withdraw.py`, `j_concurrent.py`, `j_backup.py`, `j_clear.py`, `j_extra.py`; helpers `lib.py`, `api.py`, `srv.py`).
